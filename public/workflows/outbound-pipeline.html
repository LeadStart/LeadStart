The handoff · queue-behind

What triggers an enrichment run

Three triggers lead to the same enqueue function, and a one-active-run-per-org rule decides whether contacts run now or wait in the queue.

SYSTEM · enqueueEnrichment

Enqueue — three ways in

1. A finished LinkedIn search auto-imports and enqueues (default). 2. An admin clicks Import/Enrich manually. 3. The drain cron re-enqueues queued contacts. Eligibility per contact: profiles if it has no email but a parseable LinkedIn profile URL · domains if it has no company domain but a company URL · activity if it has a profile URL and opted in.

The enrichment run · five phases

Phase by phase, actor by actor

One cron drives the whole run: run-apify-enrichment, every minute, one 60-second tick at a time under a 90s lease. Apify phases batch up to 100 items through start-run → poll → ingest; Million Verifier phases run inline in the tick. Two attempts per item; three consecutive batch failures fail the run and alert the owner.

Phase 3 in detail · the routed waterfall

Which method fires, and why

Every item that reaches the waterfall gets a method stamped from the run’s settings snapshot, keyed on the employee count captured in Phase 2. Big companies never get a pointless site scrape; small ones can get both barrels. Defaults route every band to pattern_mv.

SYSTEM · advancePhase routing

Size-band decision

employee_count unknown → unknown_method · below the threshold (default 50) → small_method · at or above → large_method. Each band is org-configurable in Settings → Integrations; off skips the item. The worker then processes one method group per tick.

default · direct pattern_mv

Runs inline — no Apify at all. Generates up to 6 permutations (first.last@ → first@ → flast@ → f.last@ → last@ → firstlast@) and verifies each through Million Verifier; first ok wins and writes the email.

Batching: ≤25 items/tick, 5 concurrent, 40s deadline. Catch-all guesses write only if the org toggle is on (off by default). MV only charges determinate verdicts — catch-all and unknown are free.
≤$0.022 /contact worst case typ. 1–3 credits ≈ $0.004–0.011
Fail-closed: MV outage or no credits → items error + owner alert. No key saved → items marked “MV key required.” Never guesses blind.

opt-in · ours site_scrape

Our private Apify actor site-contact-scraper (deployed 08-25). Crawls the company site + discovered contact/team pages (≤6) through a 5-tier anti-bot ladder: undici → curl_cffi TLS fingerprint → +residential proxy → Playwright+stealth → managed unblocker. Tiers 1–2 resolve most sites at ~$0.

Writes: a name-matched personal email → contacts.email · best phone (guarded) fill-only · generic inboxes → enrichment_data only, never the email field.
≈$0.003 /domain measured $0.0015–0.0029
scrape_plus_pattern: a scrape miss flips the item to pattern_mv and re-queues it — two-stage, cheapest-second.

opt-in · fallback bovi

Hosted community email finder bovi~email-finder-bulk — pays only per found email. Kept as the third-party fallback when neither in-house method fits.

≈$0.0049 /found email est. $0.02 /domain budgeted
hit → email written with provider provenance · miss → recorded, item closes
SYSTEM · writeEmail + cost stamping

Every outcome is accounted

Hits write contacts.email with the winning method as email_provider; phones and company inboxes land even on a miss. Per-item cost is stamped (MV credits × unit price, or the Apify run’s real usageTotalUsd), and the run banner reports per-method counts: “pattern + verify: N found · M miss.”

Timeline · what runs when

The cadence layer

Everything advances on Vercel cron ticks — no long-lived workers. A search usually lands in minutes (one actor run); an enrichment run then advances one phase-batch per minute-tick, so a 100-contact run typically completes in the tens of minutes, spending only while a phase is actually running.

run-prospect-searches * * * * * Advance one Scrap.io search a page at a time. 60s tick budget
run-decision-maker-enrichment * * * * * Enrich ~5 Maps businesses (3 in parallel) through the Haiku → Perplexity layers. 60s cap per business
drain-enrichment-queue * * * * * If the org with the oldest queued contact is now free, start its run (≤2,000 contacts). one org per tick

run-native-sequences */5 * * * * Pre-send MV gate (30-day cache), then ramped Gmail sending. fail-closed on MV outage · per-mailbox warmup ramp

Control surfaces

Switches, gates, and the one retired actor

Everything above is steered from Settings → Integrations. Runs snapshot these at start — flipping a switch never changes a run already in flight.

default ONauto_run_after_search

A finished LinkedIn search auto-imports to Contacts and starts enrichment. Off = curate manually with “Import to Contacts.”

default ONwaterfall_enabled

Master switch for the second-pass waterfall. Off (or all bands off) = phase skipped for new runs.

50size_threshold

Employee-count boundary between the small and large routing bands.

pattern_mvsmall / large / unknown_method

Waterfall method per size band: pattern_mv, site_scrape, scrape_plus_pattern, bovi, or off.

default OFFaccept_catch_all_guesses

Lets pattern_mv write a catch-all guess (confidence 40, flagged risky at send). Off = only deliverable verdicts write.

6scrape_max_pages

Pages the site scraper crawls per domain — 6 keeps team/leadership pages in reach, where name-matches live.

key-gatedMillion Verifier key

No key = pattern_mv items park as “MV key required” and the pre-send gate is disarmed. Key + no credits = fail-closed hold + owner alert.

key-gatedApify key

Powers sourcing, phases 1–2, site_scrape, bovi, and the live-pricing feed. The spend card in Settings shows real historical charges.

Retired: vdrmota directory scraper (Aug 24, 2026)

The old default second-pass actor pulled 10 directory leads per company hoping one matched — its single real run charged $3.96 and filled zero fields (≈$1.00/company on the free tier). There was no way to ask it for one person’s missing email.

Fully removed — provider, routing, settings. It’s the reason the waterfall is now surgical: pattern + verify by default, our own scraper for small-company sites, bovi as the only third-party fallback. Its historical spend still shows in the Apify spend card (real billing data).

Why routing by company size matters

A 500-person company’s website will never publish the decision-maker’s personal email — scraping it buys a dead info@ inbox. So the large band defaults to pattern_mv only.

For the small/local ICP the site scrape is genuinely useful — an owner’s email or a real phone number on the contact page — which is why scrape_plus_pattern exists: scrape first, pattern-verify the leftovers, cheapest path second.
